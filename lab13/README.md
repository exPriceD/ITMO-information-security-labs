# Лабораторная работа №13. Аудит защищённости приложения

Приложение на Go с формой входа и SQLite. Один сервер работает в двух режимах:
`vulnerable` до исправления и `secure` после исправления.

## Уязвимости

- SQL-инъекция при конкатенации пользовательского ввода в запрос.
- Открытое хранение паролей.
- Отсутствие ограничения попыток входа.
- Разные сообщения для неверного пароля и отсутствующего логина.

В исходниках проблемы отмечены как `VULN-01`–`VULN-04`, исправления как `FIX-01`–`FIX-04`.
В защищённом режиме используются SQL-параметры, bcrypt с солью и cost=12,
лимит попыток и одинаковый ответ при ошибке входа.

## Запуск

Нужен Go 1.24 или новее. Из папки `lab13` выполнить в двух терминалах:

```sh
go run . -mode vulnerable -addr 127.0.0.1:8080 -db vulnerable.db
```

```sh
go run . -mode secure -addr 127.0.0.1:8081 -db secure.db
```

Форма доступна на http://127.0.0.1:8080 и http://127.0.0.1:8081.
Новая база создаётся автоматически. У каждого режима должен быть свой файл базы.

Учебные записи:

| Логин | Пароль |
| --- | --- |
| admin | Admin!2026 |
| student | Study!2026 |

## Демонстрация

Для обхода входа в уязвимом режиме ввести логин `admin' -- ` с пробелом в конце
и любой неверный пароль. Защищённая версия этот ввод отклоняет.

Остальные сценарии воспроизводятся скриптом `demonstrate.py` (Python 3,
дополнительные пакеты не нужны). Для автоматического прогона сначала остановить
серверы на портах 8080 и 8081, затем выполнить:

```sh
go build -o auditlab.exe .
python demonstrate.py
```

Скрипт сам запускает обе версии, проверяет одинаковые атаки, сохраняет фактические
ответы в `evidence/latest.json` и завершает процессы. Исполняемый файл и локальные
базы в репозитории не хранятся.

## Устройство кода

- `main.go`: форма, маршруты, таблица пользователей, сессии.
- `vulnerable.go`: уязвимая проверка входа.
- `secure.go`: исправленная проверка входа и ограничение попыток.
- `demonstrate.py`: повтор четырёх сценариев до и после исправления.

Стенд слушает только loopback. Лимит составляет 5 запросов на пару IP+логин
и 30 на IP за минуту. Счётчик находится в памяти процесса. Проверка чтения базы
предполагает получение копии файла, а не удалённую загрузку базы через сайт.
